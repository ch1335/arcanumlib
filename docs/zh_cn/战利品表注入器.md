# 战利品表注入器

用 json（或数据生成）就能改**任意战利品表**：加池、加条目、改权重、替换条目、增删改条件与函数——
不改原版数据、不和别的模组抢方块/实体的掉落覆盖权，只在自己负责的那部分叠加上去。

- 包路径：`com.chen1335.arcanumlib.modules.loot.lootInjector`
- 数据包目录：`data/<命名空间>/loot_injecter/<注入器 id>.json`
- 命名空间**不限于** `arcanumlib`：自己开一个 `data/<你的modid>/loot_injecter/` 就能写自己的注入器，用的是同一套类型。

## 1. 它是怎么运行的

**应用时机**：服务端启动完成、以及每次数据包 reload（`/reload`）之后**各执行一次**，把全部注入器扫一遍并作用到战利品表上。

- **不是**在每次掷骰子时运行，所以就算写几百个注入器也不会影响掉落结算的性能；
- 每个注入器对**同一张表**只会应用一次（内部按 注入器 id × 表 去重，`/reload` 会自动重来一遍）；
- 应用顺序由 `priority` 决定（越小越先），同 `priority` 的注入器解析结果来自一个**无序** Map，所以**同一张表上的两个注入器不要依赖 priority 相同的先后关系**——要确定性就给不同的 priority。

启动日志里会出现一行汇总，用来确认运行正常（数字是示例）：

```
Loot injection: 26 injectors, 1183 loot tables, 4521 applications in 36.5538 ms
```

含义依次是：解析成功的注入器数、遍历到的战利品表数、"注入器 × 命中的表"的应用次数。这行出现就说明全部注入器都解析并执行成功了。

> **解析失败不会让游戏崩**：单个注入器解析失败只会记一条错误日志并跳过它，其余注入器照常工作。
> 排查时先看日志里有没有 `Failed to parse loot injector ...`。

## 2. 嵌套作用域模型

`ops` 是**树**，不是扁平列表。层级决定"这一项作用在什么上"：

```
顶层 ops                          → 作用于整张表（TableOperator）
├── add_pool                      （整表级叶子）
├── set_function / add_function / remove_function
├── table_custom
└── modify_pool  ← 作用域
    ├── poolSelector   选中哪些池
    └── ops                          → 作用于"每个命中的池"（PoolOperator）
        ├── remove_pool
        ├── add_entry
        ├── set_condition / add_condition / remove_condition
        ├── set_function / add_function / remove_function
        ├── pool_custom
        ├── modify_function ← 作用域
        │   ├── functionSelector    选中哪些函数
        │   └── ops                      → 作用于"每个命中的函数"（FunctionOperator）
        │       ├── remove_function
        │       ├── replace_function
        │       └── modify_condition ← 作用域
        │           ├── conditionSelector  选中函数自带的哪些条件
        │           └── ops                    → 作用于"每个命中的条件"（ConditionOperator）
        └── modify_condition ← 作用域
            ├── conditionSelector   选中池自身的哪些条件
            └── ops
        └── modify_entry ← 作用域
            ├── entrySelector       选中哪些条目
            └── ops                      → 作用于"每个命中的条目"（EntryOperator）
                ├── remove_entry / replace_entry
                ├── set_weight / set_quality
                ├── set_condition / add_condition / remove_condition
                ├── set_function / add_function / remove_function
                ├── entry_custom
                ├── modify_function ← 作用域（同上，目标是这个条目的函数列表）
                └── modify_condition ← 作用域（同上，目标是这个条目自身的条件）
```

**为什么嵌套而不是扁平**：`poolCondition` / `entryCondition` 这些选择器只写在**作用域**上，叶子 op 不再自带选择器——它天然只作用于"当前对象"。所以：

- 不可能把 `remove_pool` 写错层级（表级根本没注册这个类型，解析期直接报错）；
- 同一个 id（例如 `set_function`）在表/池/条目/函数/条件五级各注册一份，**靠嵌套层级消歧**；
- 顺序被结构编码：外层先于内层，同一层按数组顺序。

## 3. 执行语义（必读）

### 3.1 依次应用

同一个数组里的 op 按顺序执行，前一个的改动后一个能看见。

### 3.2 快照遍历 + 游标停止

作用域判定"哪些对象命中"时用的是**快照**（`List.copyOf`），所以子 op 删除当前对象不会让遍历跳项。规则是：

- **当前对象被前面的子 op 删掉了，剩下的子 op 立即停止**（不会对着已删除的对象继续改）；
- 删掉别的对象不影响当前这一轮。

### 3.3 条件的"归属"

| 想要改的目标 | 写在哪一级 |
|---|---|
| 表自身的 `functions` | 表级（`LootTable` **没有** `conditions`，所以表级没有 `set_condition`） |
| 池自身的 `conditions` / `functions` | 池级 |
| 条目自身的 `conditions`（所有条目都有） | 条目级 |
| 条目自身的 `functions`（只有单例条目有；`alternatives`/`sequence`/`group` 没有） | 条目级 |
| **某个函数自带的** `conditions` | 函数级 `modify_condition` |

最后一行是这套结构里最有价值的一层：函数自己的条件（`LootItemConditionalFunction.predicates`）用其它任何写法都够不着。

### 3.4 复合体一定会被重算

原版掷骰/结算时用的不是 `conditions` / `functions` 列表本身，而是构造时缓存好的 `compositeCondition` / `compositeFunction` / `compositePredicates`。
所有会改列表的 op **都会自动重算对应的复合体**，你不用管；但如果你自己写自定义 op，**必须自己重算**，否则"看着改了、实际没生效"。

## 4. 顶层字段

| 字段 | 类型 | 必填 | 默认 | 说明 |
|---|---|---|---|---|
| `ops` | 数组 | ✅ | — | 表级操作列表 |
| `priority` | int | | `1000` | 越小越先应用 |
| `tableSelector` | 表选择器 | | `{"type":"arcanumlib:all"}` | 这个注入器作用于哪些表 |

```json
{
  "priority": 1000,
  "tableSelector": {
    "type": "arcanumlib:id",
    "id": "minecraft:chests/simple_dungeon"
  },
  "ops": []
}
```

## 5. 表选择器（13）

决定"这个注入器要不要作用到某张表"。注册表：`arcanumlib:table_selector`。

**条目**：

- [5.1 `all`](#51-all--所有表) — 所有表
- [5.2 `id`](#52-id--表-id-精确匹配) — 表 id 精确匹配
- [5.3 `namespace`](#53-namespace--命名空间匹配) — 命名空间匹配
- [5.4 `path_prefix`](#54-path_prefix--路径前缀匹配) — 路径前缀匹配
- [5.5 `entity_tag`](#55-entity_tag--实体标签) — 实体标签
- [5.6 `block_tag`](#56-block_tag--方块标签) — 方块标签
- [5.7 `entity_type`](#57-entity_type--实体类型) — 实体类型
- [5.8 `block_type`](#58-block_type--方块) — 方块
- [5.9 `not`](#59-not--取反) — 取反
- [5.10 `any_of`](#510-any_of--任一满足) — 任一满足
- [5.11 `all_of`](#511-all_of--全部满足) — 全部满足
- [5.12 `has_pool`](#512-has_pool--表里任意池满足给定的池选择器) — 表里任意池满足给定的池选择器
- [5.13 `custom`](#513-custom--自定义判定交给-customtableselectorevent) — 自定义（判定交给 `CustomTableSelectorEvent`）

#### 5.1 `all` — 所有表

- 无参数。

```json
{
  "type": "arcanumlib:all"
}
```

#### 5.2 `id` — 表 id 精确匹配

- `*id`：<ResourceLocation> 目标战利品表资源位置，如 `minecraft:entities/zombie`。

```json
{
  "type": "arcanumlib:id",
  "id": "minecraft:entities/zombie"
}
```

#### 5.3 `namespace` — 命名空间匹配

- `*namespace`：<String> 命名空间，如 `minecraft`。

```json
{
  "type": "arcanumlib:namespace",
  "namespace": "minecraft"
}
```

#### 5.4 `path_prefix` — 路径前缀匹配

- `*prefix`：<String> 路径前缀，如 `entities/`。

```json
{
  "type": "arcanumlib:path_prefix",
  "prefix": "entities/"
}
```

#### 5.5 `entity_tag` — 实体标签

- `*tag`：<TagKey<EntityType<?>>> 实体标签，如 `minecraft:zombies`；表 id 等于该标签下任一实体的默认战利品表。

```json
{
  "type": "arcanumlib:entity_tag",
  "tag": "minecraft:zombies"
}
```

#### 5.6 `block_tag` — 方块标签

- `*tag`：<TagKey<Block>> 方块标签，如 `minecraft:logs`；表 id 等于该标签下任一方块的表。

```json
{
  "type": "arcanumlib:block_tag",
  "tag": "minecraft:logs"
}
```

#### 5.7 `entity_type` — 实体类型

- `*entity`：<EntityType<?>> 实体类型，如 `minecraft:zombie`；不展开标签。

```json
{
  "type": "arcanumlib:entity_type",
  "entity": "minecraft:zombie"
}
```

#### 5.8 `block_type` — 方块

- `*block`：<Block> 方块，如 `minecraft:diamond_ore`；不展开标签，没有战利品表的方块永不命中。

```json
{
  "type": "arcanumlib:block_type",
  "block": "minecraft:diamond_ore"
}
```

#### 5.9 `not` — 取反

- `*condition`：<TableSelector> 被取反的子选择器，见 [5. 表选择器](#5-表选择器13)。

```json
{
  "type": "arcanumlib:not",
  "condition": {
    "type": "arcanumlib:id",
    "id": "minecraft:entities/zombie"
  }
}
```

#### 5.10 `any_of` — 任一满足

- `*conditions`：<json数组> 子选择器列表（每项为 <TableSelector>），任一满足即匹配。

```json
{
  "type": "arcanumlib:any_of",
  "conditions": [
    {
      "type": "arcanumlib:namespace",
      "namespace": "minecraft"
    },
    {
      "type": "arcanumlib:path_prefix",
      "prefix": "chests/"
    }
  ]
}
```

#### 5.11 `all_of` — 全部满足

- `*conditions`：<json数组> 子选择器列表（每项为 <TableSelector>），全部满足才匹配。

```json
{
  "type": "arcanumlib:all_of",
  "conditions": [
    {
      "type": "arcanumlib:id",
      "id": "minecraft:entities/zombie"
    },
    {
      "type": "arcanumlib:has_pool",
      "pool": {
        "type": "arcanumlib:index",
        "index": 0
      }
    }
  ]
}
```

#### 5.12 `has_pool` — 表里任意池满足给定的池选择器

- `*pool`：<PoolSelector> 用来逐个判定表内每个池的池选择器，见 [7. 池选择器](#7-池选择器9)。

```json
{
  "type": "arcanumlib:has_pool",
  "pool": {
    "type": "arcanumlib:index",
    "index": 0
  }
}
```

字段 `pool` 是一个**池选择器**。

#### 5.13 `custom` — 自定义（判定交给 `CustomTableSelectorEvent`）

- `*custom_id`：<String> 交给 `CustomTableSelectorEvent` 监听者的自定义 id。
- `data`：<CompoundTag> **可选**附加数据；可写 SNBT 字符串（如 `"{team: \"red\"}"`）或普通 json 对象，省略时是**空 tag**（不是 null）；监听者用 `event.getData()` 取。

```json
{
  "type": "arcanumlib:custom",
  "custom_id": "mymod:my_check"
}
```

## 6. 表级操作（7）

写在顶层 `ops` 里。注册表：`arcanumlib:table_operator`。

**条目**：

- [6.1 `add_pool`](#61-add_pool--往表里追加一个池原版-json-池格式) — 往表里**追加**一个池（原版 json 池格式）
- [6.2 `modify_pool`](#62-modify_pool--作用域对每个命中的池应用子-ops) — 作用域：对每个命中的池应用子 ops
- [6.3 `modify_function`](#63-modify_function--作用域对表函数列表里命中的函数应用子-ops) — 作用域：对表函数列表里命中的函数应用子 ops
- [6.4 `set_function`](#64-set_function--替换表自身的函数列表) — **替换**表自身的函数列表
- [6.5 `add_function`](#65-add_function--追加到表自身的函数列表) — **追加**到表自身的函数列表
- [6.6 `remove_function`](#66-remove_function--按函数类型-id-移除表自身的函数) — 按函数类型 id 移除表自身的函数
- [6.7 `table_custom`](#67-table_custom--交给-tablecustomopevent-的监听者) — 交给 `TableCustomOpEvent` 的监听者

#### 6.1 `add_pool` — 往表里**追加**一个池（原版 json 池格式）

- `*pool`：<json对象> 原版随机池（`rolls` / `bonus_rolls` / `entries` 等），整池追加到表上。

```json
{
  "type": "arcanumlib:add_pool",
  "pool": {
    "rolls": 1.0,
    "bonus_rolls": 0.0,
    "name": "my_extra_pool",
    "entries": [
      {
        "type": "minecraft:item",
        "name": "minecraft:diamond",
        "weight": 1,
        "functions": []
      }
    ]
  }
}
```

#### 6.2 `modify_pool` — 作用域：对每个命中的池应用子 ops

- `*poolSelector`：<PoolSelector> 选出要改的池，见 [7. 池选择器](#7-池选择器9)。
- `*ops`：<json数组> 池级操作列表（每项为 `PoolOperator`），见 [8. 池级操作](#8-池级操作12)。

```json
{
  "type": "arcanumlib:modify_pool",
  "poolSelector": {
    "type": "arcanumlib:name",
    "name": "my_extra_pool"
  },
  "ops": [
    {
      "type": "arcanumlib:remove_pool"
    },
    {
      "type": "arcanumlib:add_entry",
      "entry": {
        "type": "minecraft:item",
        "name": "minecraft:emerald"
      }
    }
  ]
}
```

#### 6.3 `modify_function` — 作用域：对表函数列表里命中的函数应用子 ops

- `*functionSelector`：<FunctionSelector> 选出要改的函数，见 [11. 函数选择器](#11-函数选择器9)。
- `*ops`：<json数组> 函数级操作列表（每项为 `FunctionOperator`），见 [12. 函数级操作](#12-函数级操作3)。

```json
{
  "type": "arcanumlib:modify_function",
  "functionSelector": {
    "type": "arcanumlib:function_type",
    "functionType": "minecraft:set_count"
  },
  "ops": [
    {
      "type": "arcanumlib:replace_function",
      "function": {
        "function": "minecraft:set_count",
        "count": 3.0
      }
    }
  ]
}
```

#### 6.4 `set_function` — **替换**表自身的函数列表

- `*functions`：<json数组> 原版物品修饰器列表（如 `minecraft:set_count`）；**覆盖**表上现有列表。

```json
{
  "type": "arcanumlib:set_function",
  "functions": [
    {
      "function": "minecraft:set_count",
      "count": 2.0,
      "add": true
    }
  ]
}
```

#### 6.5 `add_function` — **追加**到表自身的函数列表

- `*functions`：<json数组> 原版物品修饰器列表（如 `minecraft:set_count`）；**追加**到表上现有列表。

```json
{
  "type": "arcanumlib:add_function",
  "functions": [
    {
      "function": "minecraft:set_count",
      "count": 1.0,
      "add": true
    }
  ]
}
```

#### 6.6 `remove_function` — 按函数类型 id 移除表自身的函数

- `*functionTypes`：<json数组> 要移除的原版函数类型 id 列表，如 `["minecraft:set_count"]`。

```json
{
  "type": "arcanumlib:remove_function",
  "functionTypes": [
    "minecraft:set_count"
  ]
}
```

#### 6.7 `table_custom` — 交给 `TableCustomOpEvent` 的监听者

- `*custom_id`：<String> 交给 `TableCustomOpEvent` 监听者的 id。
- `data`：<CompoundTag> **可选**附加数据；可写 SNBT 字符串（如 `"{times: 3}"`）或普通 json 对象，省略时是**空 tag**（不是 null）；监听者用 `event.getData()` 取。

```json
{
  "type": "arcanumlib:table_custom",
  "custom_id": "my_table_hook"
}
```

#### 7.1 `any` — 所有池（**默认值**）

- 无参数。

```json
  "type": "arcanumlib:any"

```

#### 7.2 `index` — 池下标（从 0 开始）

- `*index`：<int> 池在表里的下标，从 0 开始。

```json
{
  "type": "arcanumlib:index",
  "index": 0
}
```

#### 7.3 `name` — 池名；**无名池永远不匹配**

- `*name`：<String> 池名；无名池永远不匹配。

```json
{
  "type": "arcanumlib:name",
  "name": "main"
}
```

#### 7.4 `has_entry` — 池里**任意**条目满足该条目选择器

- `*entrySelector`：<EntrySelector> 用来判定池内条目的选择器，见 [9. 条目选择器](#9-条目选择器15)。

```json
{
  "type": "arcanumlib:has_entry",
  "entrySelector": {
    "type": "arcanumlib:item",
    "item": "minecraft:gunpowder"
  }
}
```

```json

```

**总权重的口径**（`arcanumlib:total_weight`，以及条目级的 `weight_in_range` / `weight_share`）：
- 只算**静态基础权重**：`weight` 字段，等价于原版 `getWeight(luck = 0)`（含 `max(..., 0)` 夹取）；
- **不含** `quality × 幸运`——选择器拿不到 `LootContext`；
- **不按条目条件过滤**——原版掷骰时是经 `expand(context)` 展开的；
- 复合条目（`alternatives`/`sequence`/`group`）自身没有 `weight`，**递归累加其子树**；其中 `alternatives` 原版只走第一个条件通过的分支，这里把所有分支都算上，属**静态上界**。

#### 10.14 `modify_child` — 修改子条目

#### 10.16 `remove_child` — 移除分支

> 只对**复合条目**（`alternatives` / `group` / `sequence`）生效：当前条目不是复合条目时**跳过**，什么都不改。

#### 10.17 `move_child` — 调整分支顺序

> 只对**复合条目**（`alternatives` / `group` / `sequence`）生效：当前条目不是复合条目时**跳过**，什么都不改。

- `entrySelector`：<EntrySelector> 要搬的 child（默认 `any`；只搬第一个命中的）；
- `position`：<String> `first` / `last` / `index`（默认 `first`）；

```json

  "custom_id": "my_function_hook"
```

### 关于 `match`
语义对齐原版的 `DataComponentIngredient` 组件匹配：
- 模板保留**原始 json**，所以**只比对写出来的 key**——没写的 key 不参与，codec 的默认值不会污染结果（这是它比"先反序列化成函数再比"更有用的关键）；
- `strict` 默认 `false`：模板里每个 key 都要在候选里存在且值一致（子集匹配）；
- `strict: true`：要求与候选**完全一致**（按序列化后的 json 相等比较）；
- 数组按**有序参数**看待：要求长度一致、逐元素匹配；
- 数字按值比较（`3` 与 `3.0` 视为相等）；
- 模板里的类型 key（函数是 `"function"`，条件是 `"condition"`）**必须存在**，否则永远不匹配。
典型用途：**按参数区分同类型的函数**。例如一个条目同时有 `set_count(2)` 和 `set_count(+3)`，`function_type` 会把两个一起选中，而 `match` 能只挑其中一个。
> 注意：`match` 的模板**不会被校验**。key 写错（例如 `coun`）不会报错，只是永远匹配不上。

| `TableCustomOpEvent` | 执行 `table_custom` 时 | `{"type":"arcanumlib:table_custom","custom_id":"..."}` |
| `PoolCustomOpEvent` | 执行 `pool_custom` 时 | `{"type":"arcanumlib:pool_custom","custom_id":"..."}` |
| `EntryCustomOpEvent` | 执行 `entry_custom` 时 | `{"type":"arcanumlib:entry_custom","custom_id":"..."}` |
| `LootInjectorApplyEvent` | 每个注入器被**应用之前** | —（可整条替换，也可取消） |
> 八个 `custom` 类事件（五个选择器 + 三个操作）都另外带 `getData()`：json 里可选的 `data`（SNBT 字符串或普通 json 对象），省略时是**空 tag**（不是 null）。

> **9 个事件都带 `getRegistries()`**（含 `LootInjectorApplyEvent`）。
> 需要读注册表 / 做 codec 往返时用它，与自定义选择器 `test(...)`、自定义 op `apply(...)` 收到的 `registries` 是同一个：
>
> ```java
> RegistryOps<JsonElement> ops = RegistryOps.create(JsonOps.INSTANCE, event.getRegistries());
> ```

```java
@EventBusSubscriber(modid = MyMod.MODID)
public final class MyLootHooks {

    /** 选择器：自定义判断。拿到什么就按什么判，只需要 setResult。 */
    @SubscribeEvent
    public static void onCustomEntry(CustomEntrySelectorEvent event) {
        if (!"my_entry_hook".equals(event.getId())) {
            return;
        }

        // 例：只命中"没挂任何条件的单例条目"

        event.setResult(event.getEntry() instanceof LootPoolSingletonContainer

    /** 操作：直接改"当前条目"。entries 已经是可变列表，可以 set / remove。 */
    @SubscribeEvent
    public static void onEntryCustom(EntryCustomOpEvent event) {
        if (!"my_entry_hook".equals(event.getId())) {
            return;
        }

        event.getEntries().set(event.getIndex(), LootItem.lootTableItem(Items.DIAMOND).build());
    }

    /** 操作：改"当前池"。 */
    @SubscribeEvent
    public static void onPoolCustom(PoolCustomOpEvent event) {
        if (!"my_pool_hook".equals(event.getId())) {
            return;
        }

        PoolOperator.mutableEntries(event.getPool()).add(LootItem.lootTableItem(Items.EMERALD).build());
    }

    /** 操作：改整张表。这时已经知道是哪个注入器在改了。 */
    @SubscribeEvent
    public static void onTableCustom(TableCustomOpEvent event) {
        if (!"my_table_hook".equals(event.getId())) {
            return;
        }

        event.getTable().pools.add(LootPool.lootPool()
                .setRolls(ConstantValue.exactly(1.0F))
                .add(LootItem.lootTableItem(Items.DIAMOND_BLOCK))
                .build());
    }

    /** 整条替换：可以按表 id / 优先级重新组织一个注入器。 */
    @SubscribeEvent
    public static void onApply(LootInjectorApplyEvent event) {
        if (!"mymod:my_injector".equals(event.getInjector().id().toString())) {
            return;
        }

        LootInjector original = event.getInjector();
        event.setInjector(new LootInjector(original.id(), original.tableSelector(), original.priority(),
                List.of(new TableOperator.AddPool(LootPool.lootPool()
                        .setRolls(ConstantValue.exactly(1.0F))
                        .add(LootItem.lootTableItem(Items.DIAMOND_BLOCK))
                        .build()))));
    }
```

**实现自定义 op 时的三条硬性要求**：

1. **改完列表必须重算复合体**——判定/结算用的是 `compositeCondition` / `compositeFunction` / `compositePredicates`：
   - 条目/池的条件：`compositeCondition = Util.allOf(conditions)`
   - 条目/池/表的函数：`compositeFunction = LootItemFunctions.compose(functions)`
   - **函数自带的条件**：`compositePredicates = Util.allOf(predicates)`（字段在 `LootItemConditionalFunction` 上）
   - 复合条件自身：`composedPredicate`（字段在 `CompositeLootItemCondition` 上）
2. **增删前把列表换成可变的**（`new ArrayList<>(...)`）：列表来自 codec，可能是不可变实现。
   池级有个现成的 `PoolOperator.mutableEntries(pool)`。
3. **不要递归遍历里改列表**：作用域已经做了快照遍历，实现侧只需要处理"当前对象"。

> 需要读写的原版字段都在 `META-INF/accesstransformer.cfg` 里开了（`LootTable.pools`/`functions`、
> `LootPool.entries`/`conditions`/`functions` 等）；自己写 op 时如果要用别的字段，**检查是否已开 AT**。

## 19. 语义边界与注意事项

1. **权重是静态口径**：`total_weight` / `weight_in_range` / `weight_share` 不含 `quality × 幸运`、
   不按条目条件过滤、`alternatives` 把所有分支都累加。**不要用它们精确复现某次掷骰的概率**，
   它们适合做"挑小池 / 挑稀有条目"这类粗筛。
2. **无名池匹配不到 `name`**：原版大多数池没有名字。
3. **`tag` 与 `item_with_tag` 不是一回事**：前者匹配 `minecraft:tag` **条目**，后者匹配
   `minecraft:item` 条目并检查它的物品是否属于标签。原版表里几乎全是后者。
4. **复合条目没有 `weight` / `quality` / `functions`**：`set_weight`、`set_quality`、
   `set_*function`、`remove_function` 遇到 `alternatives`/`sequence`/`group` 会跳过；
   `conditions` 则所有条目都有。
5. **`alternatives` 掷骰只走第一个条件通过的分支**：所以你往它的子项上加条件、或者用
   `has_child` 判断时，要意识到运行时只有一个分支真正生效。
6. **同一 priority 的顺序不确定**：同一张表上的多个注入器请给不同 priority。
7. **`match` 模板不校验**：key 写错会静默失效。
8. **`replace_*` 是深拷贝**：每处替换都会重新解码一份独立实例，所以后续改动不会串味；
   代价是需要在 `RegistryOps` 下做一次 codec 往返（只发生在应用阶段，不是掷骰时）。
9. **`set_weight` / `set_quality` 的负数表示"不改"**：这是沿用旧版语义，方便直接搬旧 json；
    想真的设成 0 就写 0。
10. **`LootTable` 没有 `conditions`**：所以表级没有 `set_condition` / `add_condition` / `remove_condition`。
11. **原版没有任何地方调用 `LootTable.freeze()`**：但我们是直接改 AT 开的字段、会绕过它的
    `checkFrozen()` 守卫。将来若有谁冻结了共享表，注入会破坏它的不可变假设。

## 20. KubeJS 联动

装了 KubeJS 时，本模组会注册脚本事件组 **`ArcanumLibEvents`** 与只读绑定 **`ArcanumLib`**；没装 KubeJS 时这些代码不会被加载。

### 20.1 事件

| 事件 | 触发时机 | 脚本能拿到 | 结果 |
|---|---|---|---|
| `lootInjectorApply` | 每条注入器应用到某张表**之前** | `injectorId` / `tableId` / `table` / `injector` | `event.cancel()` 取消这次应用 |
| `tableCustom` | 执行 `table_custom` 时 | `id` / `data` / `table` | — |
| `poolCustom` | 执行 `pool_custom` 时 | `id` / `data` / `table` / `poolIndex` / `pool` | — |
| `entryCustom` | 执行 `entry_custom` 时 | `id` / `data` / `pool` / `entries` / `index` | — |
| `customTableSelector` | 判定表选择器 `custom` 时 | `id` / `data` / `tableId` / `table` | `true` / `false` |
| `customPoolSelector` | 判定池选择器 `custom` 时 | `id` / `data` / `index` / `pool` | `true` / `false` |
| `customEntrySelector` | 判定条目选择器 `custom` 时 | `id` / `data` / `index` / `entry` / `pool` | `true` / `false` |
| `customFunctionSelector` | 判定函数选择器 `custom` 时 | `id` / `data` / `index` / `function` | `true` / `false` |
| `customConditionSelector` | 判定条件选择器 `custom` 时 | `id` / `data` / `index` / `condition` | `true` / `false` |

- `entryCustom` 的 `entries` 是**可变列表**，脚本里可以直接 `set` / `remove`；
- 带结果的事件有**三种表态方式**：`return false`、`event.setResult(false)`、`event.cancel()`（`cancel` 表示 false）；都不表态就**沿用 Java 侧监听者的结果**；
- 这些事件都在服务端脚本里监听（`ServerEvents` / `StartupEvents` 那一类）。
- 三个自定义 op 与五个自定义选择器都带 **`data`**（`event.data`）：就是在 json 里写的那个可选 `CompoundTag`（SNBT 字符串或 json 对象），没写就是空 tag；
- **九个事件都带 `registries`**（`event.registries`，与 Java 侧 `getRegistries()` 是同一个对象）：需要按 codec 反序列化或反查注册表时用它；`lootInjectorApply` 还能拿到 `event.injector`（注入器本体）。

### 20.2 绑定

| 用法 | 作用 |
|---|---|
| `ArcanumLib.modId()` | `"arcanumlib"` |
| `ArcanumLib.id("common_chests")` | 得到 `arcanumlib:common_chests` |
| `ArcanumLib.lootTable("minecraft:blocks/oak_leaves")` | 按 id 取表；没有服务端或表不存在时给 `null` |
| `ArcanumLib.lootTableIds()` | 当前已加载的全部表 id（字符串列表） |

### 20.3 示例

```js
ArcanumLibEvents.lootInjectorApply(event => {
  if (event.tableId.toString() === 'minecraft:blocks/oak_leaves') event.cancel()
})

ArcanumLibEvents.tableCustom(event => {
  if (event.id === 'my_hook' && event.data.getInt('times') > 0) {
    // 直接改 event.table
  }
})

ArcanumLibEvents.customTableSelector(event => {
  if (event.tableId.getPath().startsWith('chests/')) return true
})

ServerEvents.recipes(event => {
  console.info(`战利品表数量：${ArcanumLib.lootTableIds().length}`)
})
```

### 20.4 脚本工厂

除 `ArcanumLib` 外还会注册 **14 个 Helper 绑定**，每个类里都是静态工厂方法，脚本里直接调用；每个方法都带 KubeJS 的 `@Info`（功能说明）与 `@Param`（参数作用），在 IDE 里鼠标一悬停就能看到。

| 绑定 | 提供什么 | 方法数 |
|---|---|---|
| `TableOperatorHelper` | 表级操作 | 7 |
| `PoolOperatorHelper` | 池级操作 | 12 |
| `EntryOperatorHelper` | 条目级操作 | 17 |
| `FunctionOperatorHelper` | 函数级操作 | 3 |
| `ConditionOperatorHelper` | 条件级操作 | 2 |
| `TableSelectorHelper` | 表选择器 | 13 |
| `PoolSelectorHelper` | 池选择器 | 9 |
| `EntrySelectorHelper` | 条目选择器 | 15 |
| `FunctionSelectorHelper` | 函数选择器 | 9 |
| `ConditionSelectorHelper` | 条件选择器 | 8 |
| `LootConditionHelper` | 本模组条件 + 全部原版条件 | 20 |
| `LootFunctionHelper` | 全部原版函数 | 42 |
| `NumberProviderHelper` | 全部原版数字提供器 | 9 |
| `LootEntryHelper` | 本模组条目 + 全部原版条目 | 24 |

条件、函数、数字提供器、条目这四个 Helper 还各有三个通用兜底方法：

- `of(json, registries)`：直接吃一段 json，走对应的原版 codec；
- `ofType(typeId, fields, registries)`：给出类型 id 加其余字段，例如 `ofType('minecraft:set_count', {count: 3}, event.registries)`；
- `ids()`：列出该类别当前所有可用类型 id（含本模组与其他模组注册的）。

### 20.5 命名与重载约定

- 操作与选择器的方法名用**记录名的小驼峰**（`addChild`、`modifyCondition` 等），参数与 json 字段一一对应；
- 条件、函数、数字提供器、条目用**原版工厂名**或 **json 类型 id 的小驼峰**（`randomChance`、`matchTool`、`withLootTable` 等），`@Info` 里会写明它对应哪个 json 类型；
- **同名但参数个数不同**属于合法重载，一律保留原版名字（例如两组 `setCount`、两组 `setDamage`）；
- **同名且参数个数也相同**才会改名区分，例如 `copyDataFromNbt(NbtProvider)` 与 `copyDataFromEntity(LootContext.EntityTarget)`；
- 参数的**可为空**性用 `@Nullable` 标注：凡是记录里写成 `Optional<T>` 的参数，就是「不写也行」；
- 原版那些「只是 Builder 起头、单独调用什么都不做」的方法，要么补上必要参数（如 `setAttributes(List<AttributeModifier>, boolean)`），要么不提供，避免脚本拿到空壳。

### 20.6 直接版与配置版

`LootEntryHelper` 的每个工厂都有两个版本：直接版返回**建好的条目**，配置版多一个 `Consumer`，让你先给原版 Builder 挂条件、权重或函数，再自动收尾。

```js
// 直接版
PoolOperatorHelper.addEntry(LootEntryHelper.item('minecraft:diamond'))

// 配置版：setWeight / setQuality / when（条件）/ apply（函数）
PoolOperatorHelper.addEntry(
  LootEntryHelper.item('minecraft:diamond', builder => builder
    .setWeight(3)
    .when(LootConditionHelper.randomChance(NumberProviderHelper.constant(0.5)))
    .apply(LootFunctionHelper.setCount(NumberProviderHelper.constant(4)))))
```

- `when`（挂条件）所有条目都有；`setWeight` / `setQuality` / `apply`（挂函数）**只有叶子条目**有，合成条目不给，这一点跟原版一致；
- 合成条目收的是**建好的子条目**，所以脚本里可以直接嵌套，也可以给整组挂条件；
- 这些工厂造出来的是**值对象**：条目、选择器、操作最终写进注入器 json 或交给 Java 侧 API；想在事件回调里改表，直接动 `event.table` / `event.pool` 即可。

### 20.7 本模组条目：all_of

`LootEntryHelper.allOf(...)` 对应本模组的 **`arcanumlib:all_of`** 条目：**抽中一次就把所有孩子都产出**，用在同一池里多个各自独立的概率条目。

原版 `group` / `sequence` 只是把孩子的权重摊平进候选列表，抽选仍然每次只出一个，所以「多个独立概率」用它们会退化。

```js
PoolOperatorHelper.addEntry(
  LootEntryHelper.allOf([
    LootEntryHelper.item('minecraft:diamond', b => b.when(LootConditionHelper.randomChance(NumberProviderHelper.constant(0.1)))),
    LootEntryHelper.item('minecraft:emerald', b => b.when(LootConditionHelper.randomChance(NumberProviderHelper.constant(0.3))))
  ]))
```

### 20.8 类型包装

`registerTypeWrappers` 让脚本能直接写 json 或简写值，不必逐个调工厂：

- 五种操作与五种选择器的接口都注册了各自的 `CODEC`，所以参数位置可以直接写 json 对象，例如 `{type: 'item', item: 'minecraft:diamond'}`、`{type: 'set_weight', weight: 3}`；
- `LootPoolEntryContainer` 也注册了包装：物品 id 字符串或 `ItemStack` 会变成一条 `item` 条目；
- KubeJS 自己已经包过 `ResourceLocation` / `ItemStack` / `Item` / `NumberProvider` / `LootContext.EntityTarget` 等，本模组不再重复注册。
