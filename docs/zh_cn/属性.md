# 本模组提供的属性

ArcanumLib 提供 4 条**玩家属性**，默认基础值都是 `0`——也就是**默认完全不生效**，
要用属性修饰符、`/attribute` 命令或物品属性去加值。

## 一览

| 属性 id | 名称 | 类型 | 基础值 | 范围 | 效果 |
|---|---|---|---|---|---|
| `arcanumlib:seeking` | 寻觅 | 百分比 | 0 | 0 ~ 100 | 提高**稀有生物**的刷怪权重 |
| `arcanumlib:fortune` | 时运 | 数值 | 0 | 0 ~ 100 | 加在**时运**附魔的等效等级上 |
| `arcanumlib:looting` | 抢夺 | 数值 | 0 | 0 ~ 100 | 加在**抢夺**附魔的等效等级上 |
| `arcanumlib:bonus_loot` | 额外战利品 | 百分比 | 0 | 0 ~ 20 | 按倍率**额外摇取**实体掉落与箱子战利品 |

- 四条都挂在 `minecraft:player` 上，且都是**同步属性**（客户端能读到同一个值）；
- 范围下限都是 0，所以**只能加、不能减**。

---

## 寻觅（`arcanumlib:seeking`）

刷怪时，把**稀有**生物的权重乘以 `1 + 寻觅值`。

- **什么算稀有**：该生物在整张刷怪表里的权重占比 < 阈值（默认 **2%**，服务端配置）。
  占比按「权重 × 平均每次刷新的数量」折算，免得"一次刷 4 只"的怪被低估。
- **取哪个玩家的值**：**128 格内**所有玩家里**最高**的那个（128 格就是原版刷怪距离）。
- **加成比例不封顶**：公式本身不设上限，只受属性范围 `0~100` 夹取——也就是最多 ×101。
- **怎么关掉**：把配置里的阈值设成 `0`。

> **它是整数权重**：加成量是 `四舍五入(基础权重 × 寻觅值)`。
> 所以基础权重很低的生物（例如权重 1）要寻觅值到 `0.5` 以上才看得出变化——不足 `0.5` 会被抹成 0，等于没效果。
> 权重越大的生物越平滑。

## 时运 / 抢夺（`arcanumlib:fortune` / `arcanumlib:looting`）

把属性值取整后**直接加在附魔等级上**：

| 属性 | 影响的原版掉落机制 |
|---|---|
| `arcanumlib:fortune` | `apply_bonus`（时运加掉落数量）、`table_bonus`（按等级查概率表） |
| `arcanumlib:looting` | `enchanted_count_increase`（加数量）、`random_chance_with_enchanted_bonus`（加概率） |

取哪个实体：**实体掉落**取击杀者（`ATTACKING_ENTITY`），**方块掉落**取挖矿的玩家（`THIS_ENTITY`）。

这两条属性也顺带影响本模组自己的[概率条件](战利品条件.md)（`arcanumlib:chance_modifiers` 里的
`tool_enchantment_level` 加工器）——因为走的是同一个事件。

> **注意语义**：这是**直接加等级、门槛为 0**。所以「属性 3 + 一把未附魔的镐子」等价于「时运 3」。
> 如果你的需求是"只放大已有的附魔"（没附魔就不生效），需要加一行判断，目前**不是**这个语义。

## 额外战利品（`arcanumlib:bonus_loot`）

战利品表摇完之后，按属性给出的**倍率**对**同一张表**再摇若干份，追加到原结果里。

- **倍率就是属性值**：`0.25` = 再多 25%（属性面板显示 `+25%`）；整数部分整份摇取，小数部分再摇一份、拆成单件后按比例抽样；
- **默认只对实体掉落与箱子战利品生效**：按战利品表 id 的**路径前缀**判断，默认 `entities/` 与 `chests/`，可在配置里改；
- **取哪个实体的属性**：先看击杀者（`ATTACKING_ENTITY`），没有再看 `THIS_ENTITY`（开箱子的就是它）；两者都没有（例如纯方块掉落）时倍率为 0，不增幅；
- **上限 20**：属性范围 `0 ~ 20`，最多再多 20 倍；
- **是重新摇取，不是复制**：表里的概率条目每次结果都不同，所以额外那几份是真的再摇一次；随机数与第一次共用同一个 `RandomSource`，可复现。

> **与注入器的区别**：注入器改的是**表的结构**（加池、加条目、改权重，见[战利品表注入器](战利品表注入器.md)）；
> 额外战利品不动表，只是**多摇几份**，所以它与全局战利品修改器、概率条目天然共存。

## 属性修正

属性修正（attribute adjustment）用于在读取属性数值的那一刻叠加一次性的调整量。它与属性修饰符的差别在于
生命周期：修饰符写入属性实例、参与同步并随存档保存；属性修正不写入任何持久状态，只在本次读取期间
有效，读取结束后立即移除。

### 运作方式

本模组在读取若干属性之前触发 `LivingGetAttributeAdjustmentEvent`；监听方通过事件提供的载体按运算类型
写入调整量，该调整量随后参与本次属性计算。三种运算与属性修饰符的语义一致，各自的基准值（即不调整时
的取值）如下：

| 运算 | 语义 | 基准值 |
|---|---|---|
| `ADD_VALUE` | 直接叠加到属性基础值 | `0` |
| `ADD_MULTIPLIED_BASE` | 以调整后的基础值为基准叠加 | `0` |
| `ADD_MULTIPLIED_TOTAL` | 对最终数值整体相乘 | `1` |

三个阶段的先后顺序与原版属性计算一致：`ADD_VALUE` 的调整计入基础值，因此会一并影响后两个阶段；
`ADD_MULTIPLIED_BASE` 的调整随后计入，并受 `ADD_MULTIPLIED_TOTAL` 影响；同一运算内多个监听方的写入
互为加法或乘法，与写入顺序无关。调整发生在属性自身取值范围夹取之前，因此该属性的上下限仍然生效。

### 上下文

事件携带一个上下文对象，用于说明本次读取所处的场景；监听方据此决定是否调整以及调整多少。

| 上下文 | 场景 | 携带信息 |
|---|---|---|
| `DamageContext` | 伤害结算中读取伤害倍率、护甲与护甲韧性、护甲与保护的穿透、撕裂、暴击几率与暴击伤害、投掷物伤害 | 受伤方、伤害来源与本次伤害数值 |
| `AttackingContext` | 攻击方读取攻击伤害与暴击伤害 | 攻击者与被攻击目标 |
| `LootInfoContext` | 战利品结算中读取属性 | 本次摇取的战利品上下文 |

### 读取方式

读取已计入临时调整的属性值时，使用 `AdjustmentHelper.getAttributeWithAdjusted`：该方法依次完成注册调整、
读取属性与移除调整，并返回读取结果。若读取动作需要由调用方执行（例如保留其它模组对同一调用的包装），
可改用带 `DoubleSupplier` 的重载，由它负责注册与移除、由该供应者负责读取。

```java
double armor = AdjustmentHelper.getAttributeWithAdjusted(entity, Attributes.ARMOR, new DamageContext(entity, source, damage));
```

### 示例

监听方通过 `IContext` 区分场景。以下示例表示：用木剑攻击僵尸时，攻击伤害获得等同于 +20 的修正。

```java
@SubscribeEvent
public static void onAdjustAttribute(LivingGetAttributeAdjustmentEvent event) {
    // 只关心攻击伤害这一条属性
    if (event.getAttribute().value() != Attributes.ATTACK_DAMAGE.value()) {
        return;
    }
    // 上下文必须是「攻击方读取攻击伤害」这一场景
    if (!(event.getContext() instanceof AttackingContext context)) {
        return;
    }
    LivingEntity attacker = context.attacker();
    if (attacker.getMainHandItem().is(Items.WOODEN_SWORD) && context.target().getType() == EntityType.ZOMBIE) {
        // ADD_VALUE 与属性修饰符同名运算语义一致：等同于 +20 攻击伤害
        event.getAdjustment().add(AttributeModifier.Operation.ADD_VALUE, 20.0D);
    }
}
```

- `ADD_VALUE` 的调整计入基础值，因此会一并影响后续两个阶段的倍率计算；
- 本例只在**玩家攻击**这一场景生效（`AttackingContext`），因此不会影响僵尸自身的属性。

### 注意事项

- 属性修正不持久化、不同步，读取结束即失效；
- 属性计算在每次数值重算时都会重新触发事件，因此调整是每次重算重新询问的，可以是不确定的（例如依赖随机数或随时间变化的外部状态）；
- 监听方可以在事件回调中增删属性修饰符，但是这样做除了让事情变得复杂以外没有任何意义。

## 事件

本模组目前对外提供的事件都在这里；每个事件下面标明它属于哪个模块。

### `BonusLootCheckEvent`（额外战利品）

判断「这张表要不要吃增幅」时触发 —— **它的优先级高于配置**：监听者可以强制放行（配置里没配的表也能吃）或强制拒绝（配置里配了的也能不吃）；没人改动时按配置的前缀规则走。

| 方法 | 说明 |
|---|---|
| `getLootContext()` | 本次摇取的上下文 |
| `getLootTableId()` | 正在产出的表 id |
| `isConfigAllowed()` | 配置前缀规则给出的结果（对照用） |
| `getResult()` / `setResult(boolean)` | 最终要不要增幅；初值等于 `isConfigAllowed()` |
| `allow()` / `deny()` | 强制放行 / 强制拒绝 |

```java
@SubscribeEvent
public static void onBonusLootCheck(BonusLootCheckEvent event) {
    // 让方块掉落也吃增幅（配置里默认只有实体与箱子）
    if (event.getLootTableId().getPath().startsWith("blocks/")) {
        event.allow();
    }
}
```

### `ModifyBonusLootEvent`（额外战利品）

即将增幅时触发（Java 侧，`NeoForge.EVENT_BUS`），用来**修正倍率**或整个取消：

| 方法 | 说明 |
|---|---|
| `getLootContext()` | 本次摇取的上下文（实体、方块状态、工具等都在里面） |
| `getLootTableId()` | 正在产出的表 id |
| `getOriginalRatio()` / `getRatio()` / `setRatio(float)` | 原始倍率 / 当前倍率 / 改倍率（0 或负数等于不增幅） |
| `setCanceled(true)` | 取消这次增幅（`ICancellableEvent`） |

```java
@SubscribeEvent
public static void onModifyBonusLoot(ModifyBonusLootEvent event) {
    if (event.getLootTableId().getPath().startsWith("chests/")) {
        event.setRatio(event.getRatio() * 2.0F);
    }
}
```

### `LivingAttributeChangeEvent`（属性数值变化）
任何一条属性实例的数值**真正发生变化**时触发（Java 侧，`NeoForge.EVENT_BUS`）。
触发点覆盖：改基础值、增 / 删 / 改修饰符、实体同步、读档 —— 也就是所有会让属性重新计算的操作。

| 方法 | 说明 |
|---|---|
| `getLivingEntity()` | 属性所属的实体 |
| `getAttributeInstance()` | 发生变化的那条属性实例（属性类型、基础值、修饰符列表都在里面） |
| `getNewValue()` | 变化后的数值（已把修饰符计入） |

- **只读**：不能取消，也改不了数值；要改数值请用属性修饰符；
- **同一数值只发一次**：只有真的变了才发（同步与读档时不会反复刷）；

```java
@SubscribeEvent
public static void onAttributeChanged(LivingAttributeChangeEvent event) {
    // 只关心时运
    if (event.getAttributeInstance().getAttribute().value() != ArcanumAttributes.FORTUNE.value()) {
        return;
    }

    // 时运的新值，按需处理
    double newValue = event.getNewValue();
}
```

### `LivingGetAttributeAdjustmentEvent`（属性修正）

即将读取某个属性的数值时触发（Java 侧，`NeoForge.EVENT_BUS`）。监听方按运算类型写入调整量，
该调整量仅对本次读取有效；机制与用法见[属性修正](#属性修正)。

| 方法 | 说明 |
|---|---|
| `getAttribute()` | 正在读取的属性 |
| `getOwner()` | 属性所属的实体 |
| `getContext()` | 本次读取的上下文 |
| `getAdjustment()` | 调整载体，按运算读取或累加（`get` / `set` / `add`） |

- 不可取消：调整量按运算叠加，不做整段否决；
- 仅对已接入的属性读取触发，其余属性的读取不会收到该事件。

## 配置

服务端配置 `serverconfig/arcanumlib/attribute.toml`（单人存档在 `saves/<存档>/serverconfig/` 下）：

| 键 | 默认 | 说明 |
|---|---|---|
| `spawn.rare_spawn_weight_threshold` | `0.02` | 稀有判定阈值（权重占比，0~1）；设 `0` 等于关掉寻觅 |
| `bonus_loot.bonus_loot_prefixes` | `["entities/", "chests/"]` | 吃额外战利品的表 id 路径前缀列表（默认实体掉落 + 箱子） |
